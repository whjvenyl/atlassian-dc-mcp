Two layers of config: **server env vars** (where the server points) and
**client config** (how each user connects + which PAT they present).

## Server environment

| env | default | meaning |
|---|---|---|
| `CONFLUENCE_BASE_URL` | — | e.g. `https://confluence.corp.example` — either this or `JIRA_BASE_URL` required |
| `JIRA_BASE_URL` | — | e.g. `https://jira.corp.example` |
| `PORT` | `3000` | listen port |
| `POLICY_PATH` | `./policy.yaml` | policy file, hot-reloaded — see [Policy](/policy) |
| `ENABLED_TOOLS` | — | comma-separated tool allowlist; unset/empty = all tools |
| `TOOLSETS` | — | comma-separated tool groups (`default`, `all`, or names below) |
| `NODE_EXTRA_CA_CERTS` | — | extra CA bundle for self-signed DC certs (read once at boot) |

## Tool filtering

Filtered-out tools never register — absent from `tools/list` **and**
uncallable by name. Both vars intersect when set: a tool must pass
`TOOLSETS` *and* `ENABLED_TOOLS`.

```bash
ENABLED_TOOLS="confluence_search,jira_search,jira_get_issue,jira_list_projects"
TOOLSETS="default,jira_changelog"
```

| toolset | core | tools |
|---|:-:|---|
| `jira_issues` | ✓ | `jira_get_issue` `jira_search` `jira_create_issue` `jira_update_issue` |
| `jira_comments` | ✓ | `jira_add_comment` `jira_get_comments` |
| `jira_transitions` | ✓ | `jira_get_transitions` `jira_transition_issue` |
| `jira_projects` | | `jira_list_projects` |
| `jira_users` | | `jira_myself` |
| `jira_changelog` | | `jira_get_changelog` |
| `confluence_pages` | ✓ | `confluence_search` `confluence_get_page` `confluence_get_page_children` `confluence_create_page` `confluence_update_page` |
| `confluence_comments` | ✓ | `confluence_get_comments` `confluence_add_comment` |
| `confluence_spaces` | | `confluence_list_spaces` |
| `confluence_users` | | `confluence_current_user` |

Special values: `default` = core toolsets only (marked ✓), `all` =
everything. Unknown names are ignored — **all** unknown = no tools
(fail closed).

Only the products with a URL configured register tools — a
Confluence-only deployment exposes no `jira_*` tools.

## Client config file locations

Where each user puts their PAT headers:

| client | config location |
|---|---|
| Claude Desktop (Windows) | `%APPDATA%\Claude\claude_desktop_config.json` |
| Claude Desktop (macOS) | `~/Library/Application Support/Claude/claude_desktop_config.json` |
| Claude Desktop (Linux) | `~/.config/Claude/claude_desktop_config.json` |
| Cursor | Settings → MCP → + Add new MCP server |
| VS Code / Copilot | `.mcp.json` in workspace root, or user `mcp.json` |
| OpenCode | `~/.config/opencode/opencode.json` → `mcp` section |

Shape is the same everywhere:

```jsonc
{
  "mcpServers": {
    "atlassian-dc": {
      "type": "http",
      "url": "http://localhost:3000/mcp",          // or your shared endpoint
      "headers": {
        "X-Confluence-PAT": "<confluence PAT>",
        "X-Jira-PAT": "<jira PAT>"
      }
    }
  }
}
```

## Credential header precedence

Per service, first match wins — see [Authentication](/authentication):

```txt
X-Confluence-PAT / X-Jira-PAT  >  X-Atlassian-PAT  >  Authorization
```

## Single-product setups

<Tabs inline>
  <Tab title="Confluence only">

```bash
export CONFLUENCE_BASE_URL=https://confluence.corp.example
```

Clients send `X-Confluence-PAT` (or `X-Atlassian-PAT`). No Jira tools are
registered.

  </Tab>
  <Tab title="Jira only">

```bash
export JIRA_BASE_URL=https://jira.corp.example
```

Clients send `X-Jira-PAT` (or `X-Atlassian-PAT`). No Confluence tools are
registered.

  </Tab>
</Tabs>

## Policy file

`POLICY_PATH` points at the YAML file — defaults to `./policy.yaml`,
hot-reloaded on change, gitignored (it belongs to the deployment, not the
repo). Full reference: [Policy](/policy).

```yaml
global:
  confluence: { allowedSpaces: ["TEAM", "DOC"] }
  jira:       { allowedProjects: ["SUP", "PLAT"] }
  allowWrites: false
defaults:
  confluence: { spaces: ["TEAM"] }
  jira:      { projects: ["SUP"] }
users:
  alice:
    confluence: { spaces: ["TEAM", "DOC"] }
    jira:      { projects: ["SUP", "PLAT"] }
```

## Observability

| output | where | contents |
|---|---|---|
| audit lines | stderr | one JSON per call: `tool`, resolved `user`, `denied`, `ms` |
| health | `GET /healthz` | `{"ok":true}` — unauthenticated, for probes |

Credentials are never logged — audit lines carry only the resolved
username and outcome.
