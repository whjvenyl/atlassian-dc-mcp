## Tool access control

Filtered-out tools never register — absent from `tools/list` **and**
uncallable by name. `TOOLSETS` and `ENABLED_TOOLS` intersect: a tool must
pass both.

### Toolset groups

| toolset | core | tools |
|---|:-:|---|
| `jira_issues` | ✓ | `jira_get_issue`, `jira_search`, `jira_create_issue`, `jira_update_issue`, `jira_assign_issue` |
| `jira_comments` | ✓ | `jira_add_comment`, `jira_get_comments`, `jira_edit_comment` |
| `jira_transitions` | ✓ | `jira_get_transitions`, `jira_transition_issue` |
| `jira_projects` | | `jira_list_projects` |
| `jira_users` | | `jira_myself`, `jira_search_assignable_users` |
| `jira_changelog` | | `jira_get_changelog` |
| `jira_worklogs` | | `jira_get_worklogs`, `jira_add_worklog` |
| `confluence_pages` | ✓ | `confluence_search`, `confluence_get_page`, `confluence_get_page_children`, `confluence_create_page`, `confluence_update_page` |
| `confluence_comments` | ✓ | `confluence_get_comments`, `confluence_add_comment` |
| `confluence_spaces` | | `confluence_list_spaces` |
| `confluence_users` | | `confluence_current_user` |

```bash
# unset = every toolset. Restrict to core + extras:
TOOLSETS="default,jira_changelog,jira_users"

# everything, explicitly:
TOOLSETS="all"
```

Unknown toolset names are ignored — if **all** names are unknown, no
tools are enabled (fail closed).

### Enable specific tools

```bash
ENABLED_TOOLS="confluence_search,jira_search,jira_get_issue,jira_list_projects"
```

### Read-only mode

`global.allowWrites: false` (or a service's `readOnly: true`) in
[policy.yaml](/policy) keeps write tools visible but refusing — agents
see the reason, not a missing tool. For tools absent entirely, use
`ENABLED_TOOLS`/`TOOLSETS`.

## What agents see

The MCP `instructions` explain the scope model to agent clients and tell
them **not** to retry denied calls to work around the policy. Denied calls
return an error naming the reason — e.g. which spaces the caller *is*
allowed into.
