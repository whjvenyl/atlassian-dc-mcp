### Get Issue

Full issue detail — fields, expands, comments, properties all controllable.

<Callout type="info" title="Policy">
  Refused if the issue's project is outside your scope — checked post-fetch.
</Callout>

| parameter | type | required | description |
|---|---|---|---|
| `key` | `string` | yes | issue key, e.g. `SUP-123` |
| `fields` | `string` | no | comma-separated fields, or `*all` for everything incl. custom fields. Default: the essential set |
| `expand` | `string` | no | `renderedFields` (HTML), `transitions`, `changelog`, `names` |
| `commentLimit` | `number` | no | comments to include (0–100, default `0`) |
| `properties` | `string` | no | comma-separated issue properties |
| `useDisplayNames` | `boolean` | no | add the `names` map so `customfield_*` IDs resolve to labels |
| `includeComments` | `boolean` | no | deprecated — use `commentLimit` (true ≈ 50) |

```json
{ "key": "SUP-123", "expand": "transitions", "commentLimit": 5, "useDisplayNames": true }
```

<Callout type="tip" title="Save tokens">
  The default field set is small on purpose. Pass `fields` narrowly and
  `commentLimit` — `*all` can be thousands of tokens. Response always
  includes `browseUrl` for a direct link.
</Callout>

### Create Issue

<Callout type="warning" title="Write tool">
  Refused when `allowWrites: false` or `jira.readOnly: true`. Target
  project must be in your scope.
</Callout>

| parameter | type | required | description |
|---|---|---|---|
| `project` | `string` | yes | project key |
| `issueType` | `string` | yes | e.g. `Task`, `Bug`, `Story` |
| `summary` | `string` | yes | issue summary |
| `description` | `string` | no | plain text / wiki-markup description |

```json
{ "project": "SUP", "issueType": "Bug", "summary": "Login fails on SSO" }
```

***

### Update Issue

<Callout type="warning" title="Write tool">
  Write-gated; issue's project must be in your scope.
</Callout>

| parameter | type | required | description |
|---|---|---|---|
| `key` | `string` | yes | issue key |
| `summary` | `string` | no | |
| `description` | `string` | no | |
| `assignee` | `string` | no | Atlassian username |
| `labels` | `string[]` | no | replaces the label set |
| `priority` | `string` | no | e.g. `High` |

Pass at least one field. Returns the updated issue summary.

```json
{ "key": "SUP-123", "assignee": "alice", "priority": "High" }
```

***

### Assign Issue

Assign via the dedicated assignee endpoint — or unassign. Pair with
`jira_search_assignable_users` to find a valid username first.

<Callout type="warning" title="Write tool">
  Write-gated; issue's project must be in your scope.
</Callout>

| parameter | type | required | description |
|---|---|---|---|
| `key` | `string` | yes | issue key |
| `assignee` | `string \| null` | yes | Atlassian username; `null`/empty unassigns |

```json
{ "key": "SUP-123", "assignee": "alice" }
```

***

### Get Transitions

Workflow transitions available **right now** for an issue — the input to
`jira_transition_issue`. Returns `{id, name, to}` per transition.

| parameter | type | required | description |
|---|---|---|---|
| `key` | `string` | yes | issue key |

***

### Transition Issue

Move an issue through its workflow. Transition names resolve
case-insensitively against `jira_get_transitions` — call that first,
never guess.

<Callout type="warning" title="Write tool">
  Write-gated; issue's project must be in your scope.
</Callout>

| parameter | type | required | description |
|---|---|---|---|
| `key` | `string` | yes | issue key |
| `transition` | `string` | yes | transition name or ID |
| `comment` | `string` | no | comment added with the transition |

```json
{ "key": "SUP-123", "transition": "Done", "comment": "Shipped in 1.4" }
```

<Callout type="warning" title="Workflow validators">
  Some transitions require fields set on a transition screen (e.g.
  Resolution). Jira rejects the call with its own error if so — the
  server's scope check happens first.
</Callout>
