### List Projects

All Jira projects visible to your PAT, filtered to your effective scope.
Call this first — `policyProjects` in the response is exactly the list
your `jira_search` JQL gets intersected with.

| parameter | type | required | description |
|---|---|---|---|
| — | | | no parameters |

Response:

```json
{ "policyProjects": ["SUP","PLAT"], "count": 2,
  "projects": [{ "key": "SUP", "name": "Support" }, …] }
```

### Myself

The Atlassian identity your Jira PAT resolves to (`/rest/api/2/myself`) —
the same identity `users.<name>` policy rules match on. Useful for
checking which account a PAT belongs to and what the audit log records.

| parameter | type | required | description |
|---|---|---|---|
| — | | | no parameters |

```json
{ "name": "alice", "key": "JIRAUSER10100", "displayName": "Alice A.", "emailAddress": "alice@corp.example", "active": true }
```

### Search Assignable Users

Find users who can be assigned issues in a project — call before
`jira_assign_issue` or `jira_update_issue`'s `assignee`, since DC
usernames aren't guessable.

<Callout type="info" title="Policy">
  The project (or the issue's project) must be in your scope.
</Callout>

| parameter | type | required | description |
|---|---|---|---|
| `query` | `string` | yes | name, username or email substring |
| `project` | `string` | no | project key — pass this or `key` |
| `key` | `string` | no | issue key — pass this or `project` |
| `limit` | `number` | no | 1–100, default `20` |

```json
{ "query": "alice", "project": "SUP" }
```

### Get User Profile

Look up any Jira user by username — display name, email, active flag,
timezone.

| parameter | type | required | description |
|---|---|---|---|
| `username` | `string` | yes | Atlassian username |

```json
{ "username": "alice" }
```
